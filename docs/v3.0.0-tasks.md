# Trilha Integrar — v3.0.0 (breaking change)

## Contexto

A v3.0.0 é uma mudança de posicionamento: o app deixa de ser um **questionário** (listas fechadas de simulados percorridas em ordem) e passa a ser um **banco de questões** (repositório consultável do qual o aluno monta sua própria sessão de estudo).

Além disso:

- **Identidade visual** vai ficar mais sóbria — base **branco/preto/cinza** com **accents em vermelho/vinho** inspirados no logo original (lápis vermelho, ~`#C7202A`). Hex exatos e tipografia a definir na fase de mockup.
- **Home page** vai ser reformulada com boas-vindas + 3 CTAs: Responder questões, Escrever questões, Gerar lista para impressão.
- **Simplificação de features** — sair de 7 abas para 3–4 áreas focadas.
- **Novas features** — trilhas de estudo (agrupamentos temáticos por tags, com curadoria opcional do professor) e geração de lista para impressão.
- **Migração das questões dos JSONs estáticos para o Postgres na Neon**.

Este arquivo mantém o estado das tarefas para não perder contexto se a sessão for encerrada.

## Decisões já tomadas

- **Modelo de acesso:** fluxo restritivo. **Não existe uso sem cadastro** — a home cai direto na tela de login/cadastro se não houver sessão. Aluno vê as 3 abas de aluno (Jogos, Pesquisar Questões, Responder Questões). Professor vê tudo + CTA Escrever na home + aba Imprimir Lista + tela de aprovação de trilhas. Cadastro público cria aluno; **admin promove aluno → professor** via painel de admin. Essa decisão **reverte propositalmente** o comportamento do commit `b9ec092 play without logging in`.


- **Fluxo principal do aluno:** buscar/filtrar questões (montar a própria sessão).
- **Modos de estudo do aluno:** três dentro da aba **Responder Questões** — (1) prova completa, (2) sorteio, (3) trilhas. A quarta forma (busca/filtro) vira a aba própria **Pesquisar Questões**, reaproveitando a UI de busca que hoje existe na criação de listas do professor (agora disponibilizada também ao aluno).
- **Prova Completa (modo 1):** EnemPicker atual **sai**. Vira um formulário simples — aluno escolhe **área** (radio: math / nature / linguagens / humanas) + **ano** (dropdown: 2018–2025+), clica "Iniciar". Sem a matriz colorida atual.
- **Sorteio (modo 2):** parâmetros mínimos — **quantidade** (5, 10 ou 20) + **área** (todas / math / nature / linguagens / humanas). Sem filtros de tag/dificuldade/ano (quem quer isso usa Pesquisar Questões).
- **Trilhas de estudo:** conjunto de questões do mesmo tema, filtro por tags como base, professor pode selecionar manualmente. **Qualquer usuário pode criar uma trilha, mas ela só fica visível ao público após aprovação de um professor.** Precisa existir uma tela onde o professor vê trilhas pendentes de aprovação.
- **Navegação:** 4 abas fixas — **Jogos**, **Pesquisar Questões**, **Responder Questões**, **Imprimir Lista**. (Show do Milhão e Desafio Diário ficam ambos como sub-itens dentro de Jogos; a busca/filtro do banco vira "Pesquisar Questões" como aba própria.)
- **Layout da home:** 3 cards grandes lado a lado com título/subtítulo em cima. A home fica **acima** da navegação por abas: mensagem de boas-vindas + 3 CTAs (Responder → aba Responder; Imprimir → aba Imprimir; Escrever → tela separada só para professor, fora das 4 abas).
- **Header (top bar):** botão dedicado do **caderno** (painel lateral sob demanda) + **avatar do usuário** com dropdown ("Meu perfil", "Tema claro/escuro", "Sair" e, para prof/admin, atalhos para Escrever/Imprimir/Trilhas pendentes). Não há botão de tema separado no topo — fica no menu do avatar.
- **Persistência das questões:** migrar dos JSONs estáticos para o Postgres na Neon. Tabela **`multiple_choice_questions`** (nome reflete o escopo — suporta qualquer questão de múltipla escolha, não só ENEM), com **PK SERIAL** (auto-incremento inteiro). O `alternatives JSONB` acomoda número variável de alternativas.
- **Escopo da primeira migração:** **todos** os JSONs — ENEM (32 arquivos, ~1440 questões) **+** listas de professor (`ricardo_lista1.json` e outras). Os JSONs em `public/` **ficam preservados** como fonte de auditoria.
- **Contextos:** `contexts.json` **não** migra junto — vira uma tarefa separada (uma tabela `contexts` própria numa segunda leva). Enquanto isso, `multiple_choice_questions.context_key TEXT` mantém a ligação com o JSON.
